pub fn branch_enc_cycle_count(&self) -> (bool, u16)

§BranchEncCycleCount()

The first return result is ‘1’ if either of the following is true, and ‘0’ otherwise:

  • This is the first Branch record after the PE exited a Prohibited Region.
  • This is the first Branch record after cycle counting has been enabled. If the first return is ‘0’, the second return result is the encoded cycle count since the last branch. The format of this field uses a mantissa and exponent to express the cycle count value.
  • bits[7:0] indicate the mantissa M.
  • bits[13:8] indicate the exponent E. The cycle count is expressed using the following function: cycle_count = (if IsZero(E) then UInt(M) else UInt(‘1’::M::Zeros{UInt(E)-1})) A value of all ones in both the mantissa and exponent indicates the cycle count value exceeded the size of the cycle counter. If the cycle count is not known, the second return result is zero.

pub fn add_er( &mut self, sf: bool, m: Register, option: u8, imm3: u8, n: Register, d: Register, )

ADD (extended register): Add extended and scaled register

This instruction adds a register value and a sign-extended or zero-extended register value, followed by an optional left shift amount, and writes the result to the destination register. The argument that is extended from the <Rm> register can be a byte, halfword, word, or doubleword.

cpu.__dbg_set_x(0, 1);
cpu.__dbg_set_x(1, 2);
// `ADD X2, X0, X1, UXTB #3`
cpu.add_er(true, 1, 0b000, 3, 0, 2);
assert_eq!(cpu.__dbg_get_x(2), 17);

We get 17 because 17 = 1 + (2 << 3) The ExtendType is not very consequential because we are dealing with such small values.

cpu.__dbg_set_x(0, 1);
cpu.__dbg_set_x(1, 500);
// `ADD X2, X0, X1, UXTB #3`
cpu.add_er(true, 1, 0b000, 3, 0, 2);
assert_eq!(cpu.__dbg_get_x(2), 1953);

We get 1953 because 1953 = 1 + (244 << 3), where 244 = 500 & 0xFF (due to UXTB extending)

cpu.__dbg_set_x(0, 1);
cpu.__dbg_set_x(1, 500);
// `ADD X2, X0, X1, UXTD #3`
cpu.add_er(true, 1, 0b011, 3, 0, 2);
assert_eq!(cpu.__dbg_get_x(2), 4001);

Without the masking to byte-width, we get 4001 instead.
